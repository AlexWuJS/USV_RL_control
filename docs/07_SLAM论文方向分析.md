# 07 · SLAM 建图定位方向：硕士论文选题分析

> 依据：对 little-boat-motion-control 全仓代码走读、docs/00~06、`/home/jetson/bags` 水试 bag 清单与地图产物（scans.pcd / scans.yaml / map.pgm）的核对。
> 本文只做分析，不改任何代码。整理时间：2026-10-13。

---

## 1. 结论先行（TLDR）

| 推荐 | 选题 | 定位 |
|------|------|------|
| ★ 首选（算法型） | **面向内陆水域无人艇的 RTK/LiDAR/IMU 多源融合定位方法研究** | 解决湖心等特征退化场景的定位连续性与精度（即操作单里已写明的"定 RTK 兜底参数"） |
| ★ 首选（工程/专硕型） | **无人艇多会话建图、地图维护与鲁棒重定位系统** | 解决"每次下水人工重定位 + 地图同源门禁 + 先验图维护"的体系问题 |
| 支撑章节（必做） | 水面点云预处理与退化感知（水面杂波、艇体自回波、特征丰富度度量） | 成本低、证据全（0930 实测自回波 0.8~1.4m），为上面两条服务 |
| 不建议做主线 | 语义 SLAM（艇上无相机）、纯传感器标定（体量不够撑一篇硕士论文） | — |

**两个硬前提**（不满足则论文实验无法开展）：
1. **补录原始数据**：现有 bag 只有 `/Odometry`、`/cloud_registered_body`、`/fix` 等处理后话题，**没有 `/livox/lidar`、`/livox/imu`**——无法重放、无法改进 SLAM 前端。
2. **采评估基准**：RTK 固定解作为参考轨迹 + 场景分层标注（码头/岸边/湖心/树荫），并记录水位。

## 2. 现状盘点（论文的"起跑线"）

### 2.1 SLAM 家底

| 环节 | 现状 | 论文含义 |
|------|------|----------|
| 里程计 | FAST-LIO（港大开源，ESIKF + ikd-Tree），MID-360 内置 IMU，`extrinsic_est_en: false`，`time_sync_en: false` | 开源集成，**无自研算法改进** → 论文必须有自研改动 |
| 定位 | FAST-LIO-LOCALIZATION：低频（0.2~0.5Hz）Open3D ICP 配准先验 PCD × 高频 LIO 递推；初值需 RViz 人工给（2D Pose Estimate） | 有"地图匹配约束漂移"效果（953m 环湖 CTE 中位 0.49m 得益于此），但**湖心 ICP 失配 → 退化为纯 LIO 漂移**；人工初值是明确短板 |
| 建图 | 单会话 FAST-LIO 建图存 PCD（`scans_日期.pcd`），pcd2pgm 转 2D 栅格供 A*；**无回环、无位姿图** | 大范围/多会话建图一致性无解 → 论文空间 |
| 全局参考 | RTK（quality=4）在艇上，但**只喂 GPS 导航链（point_nav），不进 SLAM** | 融合的最直接抓手：硬件已就位 |
| 输出质量 | `/Odometry` 的 twist 恒零（实测 2.3 万条全零，全靠位姿差分凑速度） | 里程计输出不完备，本身就是一个可改的软肋 |
| 标定 | 安装角硬编码 `+91.5°`（huamo），LiDAR-IMU 外参人工写死 | 标定体系的可复现性可成为论文一节 |

### 2.2 数据资产（论文实验基础）

- `/home/jetson/bags/`：0927~1002 共 16 个 bag（合计 11GB），含 1002 环湖 10 分钟、计划 953m/实际 931m、CTE 中位 0.49m 的完整航线（`docs/figures/1002_loop_nav/` 已有成图脚本与图）。
- 地图产物：`sentry_slam/{scans.pcd, scans.yaml, map.pgm}` 先验图 + 2D 规划图；曾发生过"先验图被覆盖"事故（修改说明_20260923），修复过程本身就是"地图管理"方向的素材。
- **缺口**：原始 LiDAR/IMU 未录；多会话（跨天、跨水位）建图数据未系统采集；RTK 与 LiDAR 无统一时间基准（`time_sync_en: false`）。
- **立刻可做**：1002 等 bag 里同时录了 `/fix`（RTK）与 `/Odometry`，离线对比即可产出 FAST-LIO 漂移初评（按岸边/湖心分段）——不用下水就能出第一张图。

### 2.3 痛点清单（全部有文档/实测证据，即论文的"问题定义"）

| # | 痛点 | 证据 |
|---|------|------|
| 1 | **湖心特征退化**：远离岸线后 LiDAR 无回波/稀疏，重定位 ICP fitness 下降，漂移不受约束 | 操作单项目 5"湖心定位专段"；"产出湖心 fitness、漂移速率 → 定 RTK 兜底参数" |
| 2 | **重定位依赖人工初值**，每次开机要 RViz 点 2D Pose Estimate；"重定位未收敛前点云不显示" | 水试手册 §1.1；03 号手册"启动后如定位漂移，RViz 给初始位姿" |
| 3 | **无回环/位姿图**：建图误差不可闭环；定位期漂移只靠 ICP 碰运气 | FAST-LIO 原生无回环；环湖图靠 ICP 兜住 |
| 4 | **多会话一致性/地图维护**：先验图被运行期覆盖事故；PCD+2D 图必须同源；水位/浮标变化后地图不更新 | 修改说明_20260923；水试手册"地图管理纪律/地图门禁四判据" |
| 5 | **水面杂波与艇体自回波**：艇体结构 0.8~1.4m 恒定回波污染观测；水面飞溅/远岸低质回波 | 0929 取证；`cloud_min_range=1.0m` 补丁；RL 扇区高度带 -0.3~+1.0m |
| 6 | **里程计输出不完备**：twist 恒零；速度全靠位姿差分+低通 | 0927 bag 取证；`1713c45`、`66c236d` |
| 7 | **标定债**：`+91.5°` 硬编码；LiDAR-IMU 外参未在线估计；RTK/雷达时间未同步 | 04 号 Q5；mid360.yaml |

## 3. 方向候选

### 方向 A（推荐主线·算法型）：RTK/LiDAR/IMU 多源融合定位
- **题目示例**：《面向内陆水域无人艇的 GNSS/LiDAR/IMU 多源融合定位方法研究》
- **研究问题**：单一 LIO 在开阔水面退化、单一 RTK 在岸边多路径/树下失效且无姿态、低频——水岸两个"退化区"正好互补，如何自适应融合？
- **技术路线**（由浅入深三档，可按时间选档）：
  1. **松耦合**：ESKF 中以 RTK 位置/对地速度（`/vel` 已有 RMC 地速）+ 航迹向为观测，融合现有 FAST-LIO 输出；坐标对齐（WGS84 → ENU → camera_init）与杠杆臂标定。
  2. **退化自适应**：用 ikd-Tree 最近邻数/几何条件数在线度量 LiDAR 退化度，与 GNSS 解质量（fix/float/差分龄期/卫星数）联合调权；退化时降 LiDAR 权重、靠 RTK 与运动学约束维持，恢复后自动切回。
  3. **紧耦合**：RTK 原始伪距/载波观测进滤波（工作量大，硕士谨慎）。
- **可写创新点**：面向水岸场景的"双向退化自适应"策略；平面运动约束（2.5D）在 ESIKF 内的形式化；用现有控制链给出"定位精度 → CTE 跟踪误差"的闭环定量传导分析（有 LOS/RL 对照组，是别人没有的实验条件）。
- **实验**：岸边/湖心/码头分层；指标：ATE/RPE（evo）、漂移速率 m/min、湖心最大漂移、融合前后 fitness 曲线；消融：纯 LIO → +水面预处理 → +退化检测 → +RTK 松耦合 → +自适应权重。
- **风险**：紧耦合 C++ 改动深；RTK 湖心质量需实测确认（开阔水面多路径少，理论占优）。

### 方向 B（推荐为支撑章）：水面点云预处理与退化感知
- **研究问题**：水面回波、飞溅、艇体自回波、远岸稀疏点云如何系统性剔除/加权；如何在线度量"当前处于退化水域"。
- **路线**：距离图像/强度+仰角联合的水面点分割；艇体先验剔除（安装几何已知）；退化度量（匹配点数、海森条件数、法向分布熵）；退化状态下的 2.5D 约束（抑制 z/roll/pitch 漂移）。
- **价值**：可独立成章，且直接改善现有 RL 观测（扇区质量）与安全层（d_min 污染）。
- **风险**：单做体量偏小，作为主线不够，必须挂在 A 或 C 上。

### 方向 C（推荐主线·工程/专硕型）：多会话建图、地图维护与鲁棒重定位
- **题目示例**：《无人艇多会话建图与鲁棒重定位方法研究及系统实现》
- **研究问题**：每次下水要人工给初值、ICP 对水位/浮标变化敏感、"三张图同源"易错——如何让地图和重定位自动化、可维护？
- **路线**：
  1. **自动重定位**：全局描述子检索（Scan Context / BTC / 面向水面的轻量 BEV 描述子）+ RTK 粗定位双通道给初值，替代人工点击；
  2. **回环与位姿图**：LiDAR 回环 + RTK 伪回环因子（RTK 开链约束），多会话地图配准融合；
  3. **地图维护**：变化检测（新浮标/撤建码头）、水位归一化高度带、地图增量更新与版本管理（契合"PCD+2D 图成对更新"现有纪律）。
- **可写创新点**：水面稀疏特征下的描述子不变性设计；"RTK 锚定的多会话地图维护"完整闭环；自动化程度（人工干预次数）作为量化指标。
- **实验**：跨日期多会话数据（现有 0927~1002 已有多场！），人为扰动（挪浮标）验证；指标：重定位成功率/收敛时间/fitness、地图融合误差、变化检测查全率。
- **风险**：描述子在稀疏水面的区分度需先验证（可先离线跑 1002 数据）。

### 方向 D（应用章/加分项）：建图表达与定位不确定性的传导评估
- 把 SLAM 输出接到规划/控制：2D 栅格膨胀策略、ESDF 一致性、定位协方差 → 安全裕度；量化"定位误差 → CTE/避障表现"。你们的 LOS/RL 对照链可直接做这个实验，工作量小、故事完整，建议作为 A 或 C 的第 6 章。

### 方向 E（不建议主线）：语义/动态感知建图
- 艇上无相机（`Eyes/` 为空），要新增硬件与学习栈，硕士体量与答辩风险都偏高；若组里有相机资源可作为"展望"。

## 5. 实验设计要点

- **场景分层**（每段单独标注起止时间）：码头/岸边（GNSS 多路径、LiDAR 丰富）、湖心（GNSS 优、LiDAR 退化）、树荫/桥下如有（双退化）、多会话（不同日期/水位）。
- **Ground truth**：RTK 固定解轨迹（岸边/湖心都可用，注意与 LiDAR 系的时间与坐标对齐）；岸边可加已知检查点（如 2 个标志物测距）。
- **指标**：ATE/RPE、漂移速率 m/min、湖心段最大偏差、重定位成功率/收敛时间/fitness 时间线、人工干预次数；控制侧：CTE 中位/P90（现有 1002 图脚本可直接复用）。
- **消融序列**（论文最重要的表）：FAST-LIO 原始 → +水面/自回波过滤 → +退化检测 → +RTK 松耦合 → +自适应权重 → +回环/位姿图。
- **对比对象**：FAST-LIO / Point-LIO（仓内已有源码）/ LIO-SAM+GNSS 或 DLIO 等开源。

## 7. 与已有研究的差异化（2025 前后公开工作）

- ISPRS 2025 淡水水域 USV 建图：GNSS/INS 后处理轨迹做初值 + NDT 位姿图 + 回环——**他们的差异化**：你们的 ICP 先验图定位 + 实时性约束（NX 算力）、内湖小艇场景。
- 已有中文学位论文《面向无人艇的多源信息融合定位与建图研究》做过"退化感知多源紧耦合（ESIKF + 协方差衰减/海森条件数）+ 先验地图长期定位"——**避开正面重复**，或把差异点放在：水岸两类互退化区（GNSS 多路径 vs LiDAR 稀疏）的联合自适应、双 IMU/双天线（如有）利用、多会话地图维护与自动化。
- DR-LIOM（2025，港口直接配准 LIO）与港口融合 SLAM（大连海事 2024，LIO-SAM 改造）：多为机械式雷达/港口场景——**你们的差异化**：MID-360 非重复扫描特性、内湖开阔水面 + 环湖 953m 实测、定位-控制闭环定量评估。

## 8. 风险清单

1. **创新度风险**：多源融合是热门命题，必须把"水岸双向退化自适应"或"多会话地图维护"至少一个做实、做深，否则易被评"工程集成"。
2. **数据风险**：无原始传感器 bag 是当前最大拦路虎，先补录再谈算法。
3. **算力风险**：NX 上跑重 ICP/描述子检索要注意实时性（现有 ICP 已是 0.2~0.5Hz 低频）。
4. **时间风险**：紧耦合 ESIKF 改动 FAST-LIO C++ 工作量大，若答辩时间紧，选"松耦合 + 自适应权重 + 自动重定位"组合，把深水区留给展望。
