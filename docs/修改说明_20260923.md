## 一、新增能力：A* 多目标串规划

**做了什么**（`guidance/planner/a_star_planner`）

- 新增 `/goal_sequence` 订阅：接收一串目标点，**逐段规划并拼接为一条连续路径**（第 i 段起点 = 上一段终点），一次发布到 `/waypoints_path`；
- 起点优先取 TF（`map→camera_init`）的艇位，取不到回退 `/initialpose`（保留原单目标流程）；
- 新增 `/planner_status`（latched）反馈规划结果：`OK: N goals, M poses` / `ERROR: waypoint N unreachable (abort)`；
- 航点去重（`min_seg_len`，默认 1m）；不可达处理策略可配（`abort` 默认 / `skip`）；
- 可选 `fill_orientation`（默认关闭）：给路径点补切向朝向（会激活 huamo 的转弯分支，默认不动）。

**作用**：一条指令即可让艇按顺序经过多个目标点；任务链有缺口时**不下发残缺路径**，避免"跑到一半没路了"。

**配套工具**（同包 `scripts/` + 地面站节点）

| 工具 | 作用 |
|------|------|
| `waypoint_collector.py` | RViz 点击采集目标点（带编号标记/连线），一条命令提交，不用手抄坐标 |
| `verify_goal_sequence.py` | 发目标序列并**自动校验**路径连续性（相邻点间距 ≤0.708m）与航点覆盖 |
| `fake_odom_follower.py` + `a_star_demo_sim.launch` + `a_star_sim.rviz` | 无硬件仿真：虚拟艇沿规划路径匀速重放，可完整演示多目标规划与 LOS 跟踪 |
| `test_goal_sequence_offline.sh` | 一键离线自检（自动起 map_server + 节点，输出 PASS/FAIL） |
| `publish_ground_waypoints_node` 的 `via_astar` 模式 | 地面站 P 帧航点改走 A* 串规划（原直发模式保留） |

**验证**：离线 8 项用例（串规划/顺序/去重/清空/多轮复跑/abort/覆盖度/连续性）+ 3 轮多目标重放回归，路径连续、航点全覆盖、**零野点**。

## 二、修复：huamo 控制链路的两个 bug + 参数化

**1. 路径末端野前视点**（`guidance.cpp`）
`path.poses.erase()` 之后迭代器 `closest_it` 已失效，后续 `std::next(closest_it, delta)` 越界读内存 → 临近终点时会算出远离路径的"野前视点"（RViz 上表现为一条横穿的直线）。
修复：erase 后最近点即下标 0，全部改为下标访问 + 按剩余点数钳制；剩余点数不足前视距离时 LOS 直接钉在路径终点。

**2. 停止周期发布 (0,0) 野点**（`huamo_node.cpp`）
`huamo_run()` 内局部 `LOS_` 遮蔽了全局同名变量，任务结束（stop 分支提前 return）时该局部变量保持零初始化，却仍被发布出去。
修复：`has_path_` 已置 false 的周期直接返回，不再发布 LOS 与推力。

**3. 新增 `speed_max` 参数**（`guidance.h` / `huamo_node.cpp` / launch）
期望巡航速度上限参数化（默认 2.0 保持原行为），首次水试可用 `speed_max:=0.8` 降速。

**4. 轨迹累积与任务取消**
- `/motion_path`、`/LOS_path` 此前**只加不清**：单条消息携带任务开始至今的全部轨迹，实测跑到 2 小时时单条 6MB、10Hz 发布 → **60MB/s 磁盘写入**（本次水试 bag 只录到 15 秒、磁盘被写满的直接原因）。现改为**新任务到达时清空**，每条消息只含当前任务轨迹（实测双任务点数为 639 → 639，不再翻倍）；
- 新增"**空路径 = 取消任务**"分支：清空路径/轨迹并显式输出中位 PWM 停车（thruster_manager 会保持最后收到的 PWM，必须显式发停车）。采集器的 `clear` 与手动发空 `nav_msgs/Path` 到 `/waypoints_path` 都会触发。

**验证**：仿真 3 轮重放回归 + 双任务点数不累积验证。

## 三、修复：定位/地图链路（本次水试失败的主因）

**现象**：RViz 里实时点云与静态先验地图无法重合（含角度偏差）；重定位日志显示成功（fitness 0.93）但对不上。

**根因**：

1. **每次运行退出都会覆盖重定位基准图**：`mid360.yaml` 的 `pcd_save_en` 被改为 `true`（本地未提交改动，偏离仓库默认的 `false`），代码把本次会话地图**写回固定文件名** `PCD/scans.pcd`——而这正是每次启动读来做重定位的文件，且保存用的是**本次开机坐标系**。事故链：2.1GB 大图 → 被覆盖成小图 → 最终写成全零坏文件（磁盘写满导致）；
2. **2D 图与 3D 基准图不同源**：RViz/A\\* 用的 `map.pgm` 是 2025-04-16 的，而定位基准被换成了后续会话的图；
3. 另发现 `map→camera_init` 变换本身正常（实测 0.11m / 0.20°），**对不上的根源是两张图不是同一次建图**。

**修复**：

| # | 改动 | 作用 |
|---|------|------|
| A | `config/mid360.yaml`：`pcd_save_en` 恢复 `false` | 定位模式下不再自动保存，基准图不再被覆盖 |
| B | `launch/sentry_build_map.launch`：新增 `save_pcd` 参数（默认 false，置于 yaml 加载之后以覆盖它） | 只在建图时显式开启，且 bringup 默认关闭 |
| C | `src/laserMapping.cpp`：保存文件名加日期 `scans_YYYYMMDD_HHMM.pcd` | 建图产物不再占用先验图路径，杜绝误覆盖 |
| D | 从备份恢复与 2D 图配套的 PCD | 离线实测该图与 `map.pgm` 在 **0° 旋转下 84% 的点落在障碍栅格上**（对照组仅 20%），确认同源 |
| E | `rviz_cfg/sentry_build_map.rviz`：Fixed Frame `camera_init` → `map` | **单个 RViz 窗口**即可同时看点云对齐、路径、编号航点并直接打点（此前需开两个窗口，且容易在 camera_init 系窗口错误打点） |

**附带修复**：`global_localization.py` 首次定位直接采用配准结果（此前从单位阵开始缓慢 EMA 平滑），收敛更快。

## 六、验证情况与遗留

**已离线验证**：多目标规划 8 项用例 + 3 轮回归；huamo 双任务轨迹不累积；恢复后的 PCD 文件校验（大小/头部/点数 3268 万点）；RViz 配置加载测试。

**待实艇验证**（下一步）：地图门禁四判据（点云与 `/prior_map` 重合、`tf_echo map→camera_init` 数值、fitness、**退出后 `scans.pcd` 时间戳不变**）→ 单目标回归 → 多目标水试。

**已知遗留**：

1. RL 目前**只能 shadow**：Phase 5（huamo 接 `rl_cmd` + 安全兜底）未实现，Stage 2 成功率 74%（门槛 90%），且 `k_r`/`r_max` 需用实船数据回归修正；
2. 栅格 A* 路径为阶梯状：控制器前视点已平滑（实测瞄准方向平均变化 0.49°/周期），但**折角处仍生硬**（最大 46°/周期）；路径平滑或换 Hybrid A* 留待水试通过后做 A/B；
3. 磁盘需保持 ≥20G 可用（曾因写满导致地图文件损坏与 bag 录制中断）；bag 录制统一使用 `--lz4 --split` 且不录 `/motion_path`。
