# 02 · 模块职责手册

> 标注约定：`【实艇】`= 实艇主链在用；`【仿真】`= Gazebo/VRX 链；`【标定】`= 岸上调试/标定工具；`【遗留】`= 未接入主链的历史代码；`【新】`= 本轮 RL 改造新增。

---

## 1. 传感器层 `sensor/`

### gps_common 【实艇】
- **职责**：RTK GPS NMEA 解析与 GPS 相关工具节点。
- **关键文件**：`launch/rtk_nmea.launch`（nmea_topic_serial_reader + nmea_topic_driver → `/fix`）。
- **发布**：`/fix`（sensor_msgs/NavSatFix）。
- **其他节点**：`full_odom.cpp`/`fuse.cpp`（GPS+IMU 融合 → `/odom_local`）、`utm_odometry_node.cpp` —— GPS 链辅助工具，主链未用。

### 仓库根 `nmeadriver/` 【实艇】
- **职责**：自带修改版 nmea_navsat_driver，从 RMC 语句发布对地速度。
- **发布**：`/vel`（TwistStamped）——**注意是 ENU 地速分量**（speed·sin/cos(true_course)），不是体轴速度（04 号文档 Q8）。

### wit_imu 【实艇】
- **职责**：WitMotion IMU 驱动。
- **发布**：`/imu/data`（Imu，四元数艏向 + 角速度）。`sanchi_amov/`（100D4）为备选 IMU。

### livox_ros_driver2 【实艇】
- **职责**：MID-360 雷达驱动。
- **发布**：`/livox/lidar`（CustomMsg）、`/livox/imu`。

### NEXTE_Sentry/sentry_slam/FAST_LIO_LOCALIZATION 【实艇】
- **职责**：激光建图 + 先验地图定位。
- **入口**：`launch/sentry_build_map.launch`（bag_mode / enable_localization 开关）。
- **发布**：`/Odometry`（camera_init 系，实艇控制状态唯一来源）、`/cloud_registered_body`（体轴点云，RL 扇区化输入）、`/cloud_registered`、TF `map→camera_init`（transform_fusion）。
- **配套**：map_server 发布 `/prior_map`（scans.yaml 2D 栅格）；`costmap_nodes.launch` 动态 costmap；`global_localization.py` 全局重定位（RViz 给初值）。
- Point-LIO、sentry_nav、sentry_decision 等：Sentry 平台移植件，实艇未接入主链 【遗留】。

## 2. 通信层 `message/`

### tcp 【实艇】
- **职责**：地面站 TCP 通信与船体状态管理。
- **关键文件**：`src/sys_status_node.cpp`。
- **协议**：`S` 帧（模式/遥测开关）→ `/ship/ship_info`；`P` 帧（GPS 航点，虚拟起/终点包裹）→ `/ship/rtk_point`；`K` 帧（摇杆）→ ship_info.joystick。
- **注意**：`default_auto_control` 参数（bringup 里默认 true）会在无地面站时强制自主模式 —— 调试便利，出海须知悉（04 Q11）。

### usart 【实艇】
- **职责**：MCU 串口（`/dev/32port`）。
- **订阅**：`/controller`（thruster_manager 输出）→ 下发 PWM；**发布**：`/usart/data`（MCU 遥测：电压/模式/arming/PWM 回报）。

### logger
- 日志库（LOG_INFO 宏等）+ 音频管理，被各节点链接。

## 3. 规划/引导层 `guidance/`

### planner/a_star_planner 【实艇·链B】
- **职责**：2D 栅格 A* 全局规划。
- **订阅**：`/prior_map`、`/initialpose`（RViz 2D Pose Estimate）、`/move_base_simple/goal`（RViz 2D Goal）。
- **发布**：`/waypoints_path`（nav_msgs/Path，map 系，0.5m 间距）。
- **已知缺陷**：发布的 pose.orientation 为单位四元数（yaw 恒 0），huamo 的转弯检测因此失效（04 Q4）。

### planner/Hybrid-Astar-ESDF-main 【实艇可选·链B】
- **职责**：运动学约束 Hybrid A* + 平滑器，`run_hybrid_a_star.launch`。
- **发布**：`/waypoints_path`（平滑路径，**带真实朝向**）——与栅格 A* 二选一。

### los_guidance 【仿真/参考】
- **职责**：教科书式 LOS 引导类 `SetOfLos`（`set_of_los.cpp`）：路径系 CTE、常值/时变前视、返回 {desired_course, desired_speed}。
- **状态**：被 waypoint_los_pid（Gazebo 链）引用；**实艇不跑**。desired_speed 是固定参数，无自适应减速。RL 观测/奖励的 CTE 定义参考此实现。

### path / publish_waypoints 【仿真/测试】
- path.launch：直线/正弦/方形测试轨迹生成 → `/my_path`、`/global_path`。
- publish_waypoints：RViz 点击收集航点 → `/waypoints_path`。

### rl_local_planner 【新】
- **职责**：SAC 强化学习局部规划器（引导层），详见 05 号文档。
- **组成**：`rl_common/`（双端共用契约层）、`msg/NavCmd.msg`、`scripts/rl_local_planner_node.py`（shadow 节点）、单测与假数据源。
- **当前状态**：Shadow 已在 NX 实跑验证；闭环（active）需 Phase 5 huamo 集成后才可用。

## 4. 控制层 `control/`

### huamo 【实艇·链B 核心】
- **职责**：A* 路径跟踪执行器 = LOS 引导 + 增益调度滑模 + PWM 差速混合，三合一单节点。
- **关键文件**：`src/huamo_node.cpp`（主循环/状态提取，/Odometry 驱动 ~10Hz）、`src/guidance.cpp`（变视距 LOS + 速度决策）、`src/huamo.cpp`（speed_huamo/yaw_huamo 滑模）、`src/pwm_data.cpp`（差速混合：±100% → 1500±250 PWM）。
- **订阅**：`/Odometry`、`my_path`（被 launch remap 成 `/waypoints_path`，TF 转到 camera_init）。
- **发布**：`/auto_thruster_pwm`、`/motion_path`、`/LOS_path`（可视化）。
- **注意**：艏向约定含 `+91.5°` 硬编码偏置（04 Q5）；转弯时 `desired_speed=2.0` 满速（04 Q2）；自主模式不可倒车（04 Q9）。

### adjust_pid 【实艇·链A + 标定】
- `point_nav_node`：**链A 核心**。GPS 航点 → 角度 PID + 速度 PID → 直接出 PWM，100Hz，发布 `/auto_thruster_pwm`。
- `adjust_angle_pid / adjust_speed_pid / adjust_speed_value_pid / adjust_location_pid`：四个 PID 标定节点（各自 launch），**也都发布 `/auto_thruster_pwm`** —— 标定时严禁与导航节点同时运行。
- `record_data_node`：订阅 `/vel` 记录数据。

### thruster_manager 【实艇】
- **职责**：执行层唯一仲裁。10Hz：`is_auto_control` → 透传 `/auto_thruster_pwm`；否则 `is_keyboard_control` → 摇杆差速混合（死区/圆形限幅/±300 PWM）；否则中性。
- **钳位**：所有输出 1200~1800。侧推字段恒中性（硬件未用）。

### los_pid_follow 【仿真/调试残留】
- 变视距 LOS + PID 的另一套实现，但 `desired_heading = -3` 硬编码（04 Q6）——**不可用状态**，仅历史价值。

### follow_controller 【仿真】
- `pid_controller.cpp`：course/speed 双 PID + 阻尼前馈 + `thrustAllocation()` 推力分配矩阵。Gazebo 链专用；其阻尼模型与分配矩阵是 RL 仿真的参数来源之一。

## 5. 编排层

### control_manage 【仿真】
- `waypoint_los_pid.cpp`：SetOfLos + PidController 组合，WAMV 话题（`/wamv/...`）；`waypoints_follow.launch` = VRX Gazebo 完整仿真入口。**实艇不跑**，但它展示了"LOS→PID→推力分配"的标准分层，是 RL 设计的参考架构。

### bringup 【实艇】
- `bringup.launch`：底座（usart + tcp + sys_status + thruster_manager + 可选 IMU/RTK/雷达+FAST-LIO）。
- `sliding_mode.launch`：底座(仅雷达) + huamo —— 链B 的免 GPS 变体。

### system_identification 【标定】
- `sys_ident.cpp`：艏向 Nomoto 辨识（定常回转 K、Z 形 T/n3），TCP 发 `T1/T2/T3/T4` 触发，直接向 `/controller` 发试验 PWM（绕过 thruster_manager，标定专用）。
- **已知缺陷**：Z 试验结果解析时 `rudder_data_[k]` 对空 vector 越界写（04 Q3）。

### USV/ 【遗留】
- USV_description（URDF）、USV_nav（move_base/amcl）、USV_ship（robot_localization）—— 历史/仿真遗留，实艇主链未使用。

### common 【工具】
- `check_topic` 等话题自检小工具。
