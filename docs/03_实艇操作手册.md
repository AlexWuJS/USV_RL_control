# 03 · 实艇操作手册

> 覆盖艇上现有全部功能的操作方法。所有命令在 Jetson NX 终端执行（先 `source message_ws/devel/setup.bash`）。出海前先读 00 号文档"铁律"和 04 号文档对应条目。

---

## 1. 上电与启动顺序

1. 打开艇上电源（MCU/推进器电池、Jetson 电源独立）。
2. SSH 登录 NX：`ssh jetson@192.168.50.186`。
3. 检查串口设备存在：`ls -l /dev/32port`；RTK 串口：`ls -l /dev/gps`。
4. 按 §2~§6 选择任务对应的 launch。**同一时间只能跑一个 `/auto_thruster_pwm` 发布者。**

---

## 2. 底座启动（所有任务的基础）

```bash
roslaunch bringup bringup.launch            # 全量：IMU+RTK+雷达+FAST-LIO
roslaunch bringup bringup.launch use_lidar:=false use_rtk:=false   # 最小底座
```

包含：usart_node（MCU 串口）、tcp_node、sys_status_node、thruster_manager、wit_imu、rtk_nmea、MID360 + FAST-LIO（sentry_build_map）。

验证底座：
```bash
rostopic hz /imu/data /fix /Odometry    # 应分别 ~100Hz / 1-10Hz / ~10Hz
rostopic echo /controller -n 1          # thruster_manager 心跳（中性 1500）
```

注意：`bringup.launch` 中 sys_status 的 `default_auto_control:=true`——无地面站时也处于"自主模式"标志位。若只做传感器检查，建议临时改为 false 防止误触发推进。

---

## 3. 链A：GPS 点对点自主导航（point_nav）

**用途**：地面站下发经纬度航点序列，船依次驶过。不需要雷达/地图。

```bash
roslaunch adjust_pid point_nav.launch    # 内含最小底座（无雷达）
```

操作流程：
1. 地面站连接 TCP（tcp_node 监听）。
2. 地面站发 `P` 帧航点序列；sys_status 自动以虚拟起/终点包裹转发到 `/ship/rtk_point`，point_nav 收到后开始跟踪。
3. 参数（launch 里调）：`angle_kp/kd`（默认 12/100）、`speed_kp`（150）、`desired_speed`（0.5 m/s）。
4. 停止：地面站切非自主 → thruster_manager 中性。

监控：`rostopic echo /auto_thruster_pwm`；航向角与期望角见节点 ROS_INFO。

特性与限制：角度环反馈用 IMU 艏向（ENU），速度环反馈用 GPS 地速模长；无路径概念、无避障、无加速度限制（这是 RL 项目要解决的"激进"来源之一，见 04 Q14）。

## 4. 链B：A* 全局路径自主（huamo）

### 4.1 前提：先验地图

首次使用或场地变化需建图：
```bash
# 纯建图模式（无先验地图）
roslaunch fast_lio_localization sentry_build_map.launch enable_localization:=false
# 驾船缓慢绕场覆盖一圈后，保存 PCD（节点按配置存 scans.pcd）
```
之后需要把点云转为 2D 栅格 `scans.yaml`（sentry_build_map 定位模式会用它发布 `/prior_map`；工具：`pcd2pgm`、`Pointcloud2Map.launch`，按已有流程操作）。

日常使用：`sentry_build_map.launch`（默认 enable_localization:=true）加载 `PCD/scans.pcd` + `PCD/scans.yaml`，启动后如定位漂移，在 RViz 用 `global_localization` 的 2D Pose Estimate 给初始位姿。

### 4.2 标准启动

```bash
# 终端1：底座（含 FAST-LIO）
roslaunch bringup bringup.launch
# 终端2：规划 + 跟踪
roslaunch a_star_planner a_star_demo.launch
```

a_star_demo 内容：A* 规划器（`/prior_map` 上规划）+ huamo_node（remap 订阅 `/waypoints_path`）。

### 4.3 下发任务

RViz 中：
1. **2D Pose Estimate**（`/initialpose`）→ 设船当前位置为规划起点（应与 FAST-LIO 位姿一致）。
2. **2D Goal**（`/move_base_simple/goal`）→ 目标点；A* 立即发布 `/waypoints_path`，huamo 开始跟踪。

监控：
```bash
rostopic echo /waypoints_path | head     # 新路径
rostopic echo /LOS_path                  # huamo 前视点（可视化）
tail -f ~/.ros/log/latest/...            # 或看 launch 终端输出
```

结束/停止：路径执行完（剩余点 < 10）船自动停（desired_speed=0）；随时地面站急停。

### 4.4 变体：sliding_mode.launch

`roslaunch bringup sliding_mode.launch` —— 底座只开雷达（无 GPS/IMU）+ huamo。适合室内/已知地图场地测试。

### 4.5 Hybrid A*（可选规划器）

```bash
roslaunch hybrid_a_star run_hybrid_a_star.launch
```
运动学约束 + 平滑路径（带真实朝向，huamo 转弯检测才有效）。与栅格 A* 二选一，都在 RViz 触发。

## 5. 手动遥控与模式仲裁

- **摇杆**：地面站 `K` 帧 → ship_info.joystick → thruster_manager 差速混合（死区 0.05、圆形限幅、±300 PWM）。
- **优先级**：`is_auto_control` > `is_keyboard_control` > 中性。**自主模式激活时摇杆无效**——摇杆接管必须先由地面站切出自主模式（04 Q12）。
- **急停**：地面站断自主 → 立即中性 PWM。这是唯一与所有上层节点无关的停止通道。

---

## 6. 系统辨识试验（岸上/系泊）

```bash
roslaunch adjust_pid sys_ident.launch     # 辨识节点 + 串口 + TCP
# 注意：该 launch 不含传感器，需另开终端 roslaunch bringup bringup.launch use_lidar:=false
```
地面站发送：`T1` 定常回转（20s）、`T2` Z10°、`T3` Z20°、`T4` 计算输出 K/T/delta_r/n3。
**警告**：试验直接向 `/controller` 发 PWM（绕过仲裁），必须在系泊/岸上进行；Z 试验结果解析存在越界 bug（04 Q3），以 T1 与日志原始数据为准。

## 7. PID 标定节点（岸上专项）

| launch | 用途 |
|--------|------|
| `adjust_angle_pid.launch` | 艏向角环 PID 阶跃/方波标定 |
| `adjust_speed_pid.launch` | 速度环标定 |
| `adjust_speed_value_pid.launch` | 速度值跟踪标定 |
| `adjust_location_pid.launch`（postion_control.launch） | 定点位置环标定 |

全部直接发 `/auto_thruster_pwm`——**严禁与任何导航节点同时运行**。

## 9. 出海前检查单

- [ ] 电池电压（`/usart/data` 回报左右电池）充足
- [ ] `/fix` 有 RTK fix、`/imu/data` 艏向稳定不漂
- [ ] （链B）`/Odometry` 正常、定位无漂移、`/prior_map` 已加载
- [ ] 只有一个 `/auto_thruster_pwm` 发布者：`rostopic info /auto_thruster_pwm`
- [ ] 地面站急停演练一次（切自主→中性）
- [ ] 推进器正反响应正常（低 PWM 手动验证）
- [ ] 首次新模式：低速、小范围、开阔水域
